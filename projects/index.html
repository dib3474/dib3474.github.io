FestaPick | 축제 추천·실시간 소통 플랫폼

2025년 8~11월 · 카카오테크캠퍼스 3기 6인 팀 프로젝트 · 프론트엔드 설계 및 구현

문제

축제 참여자가 취향에 맞는 행사를 찾고, 방문 전에 궁금한 점을 묻거나 다른 참여자의 후기를 확인할 수 있는 공간이 필요했습니다. 주최 측도 같은 곳에서 축제 정보를 등록하고 공지를 전달할 수 있어야 했습니다.

맡은 역할

  • 컴포넌트 구조. 페이지 전용 요소와 공통 요소를 분리하고, 리뷰 이미지 모달은 여러 화면에서 재사용할 수 있도록 공통 컴포넌트로 옮겼습니다. 화면에서 쓰는 상수도 별도로 분리해 수정 위치를 쉽게 찾도록 했습니다.
  • 화면 테스트. 버튼 클릭과 비활성 상태에서의 동작을 단위 테스트로 확인했습니다. 축제 상세 화면의 포스터 이미지와 이전·다음 버튼은 각각 스냅샷으로 남겨 변경된 요소를 쉽게 찾을 수 있도록 했습니다.
  • API 연동. 응답 형식이 기능마다 달라 화면별 처리가 필요했습니다. 백엔드 팀과 일반 조회, 무한 스크롤 조회, 작성 API의 응답 구조와 필드 이름을 조율하고, 공통 오류 처리 함수와 로딩·오류 화면을 구현했습니다.
  • 실시간 채팅. 채팅방을 오갈 때 WebSocket 연결을 공유하도록 React Context에서 관리했습니다. 같은 채팅방의 STOMP 구독은 재사용하고, 방을 나갈 때 해당 구독을 해제하도록 정리했습니다.

기술

React, TypeScript, TanStack Query, Tailwind CSS, WebSocket(STOMP), Vitest, Testing Library, MSW

결과

팀은 참여자가 지역과 성향에 맞는 축제를 추천받고, 축제별 실시간 채팅과 리뷰로 정보를 나누는 서비스를 완성했습니다. 주최 측은 축제를 등록하고 공지를 올릴 수 있습니다. 이 프로젝트로 카카오테크캠퍼스 3기 우수상을 받았습니다.

기능별 시연 화면 · 프론트엔드 소스 코드 · 채팅 구독 코드 · 축제 상세 테스트

CrewMate | 건설 일용직 인력 중개 플랫폼

2026년 7월 · 부산대학교 클라우드 AI PBL 3인 팀 프로젝트 · 검색용 데이터 구축 및 AI 추천·보고서 검증

문제

인력사무소는 전화와 종이 기록을 바탕으로 일할 수 있는 근로자를 찾고, 건설사가 요청한 직종별 인원과 예산에 맞춰 작업조를 꾸렸습니다. 이 과정을 디지털화하려면 AI가 제안한 작업조를 실제 후보와 대조해 배정 가능한지 판단할 수 있어야 했습니다. 근로자에게 제공하는 역량 보완 보고서에는 자격과 직무 요건을 직접 확인할 수 있는 출처가 필요했습니다.

맡은 역할

  • 검색용 데이터 구축. 근로자 보고서에 쓸 건설 직종, 국가직무능력표준(NCS), 자격 정보를 공공데이터에서 수집하고 정제했습니다. 이를 검색용 문서와 메타데이터로 변환하고, S3 Vectors를 벡터 저장소로 쓰는 Amazon Bedrock Knowledge Bases에서 검색할 수 있도록 적재 과정을 구성했습니다.
  • 작업조 추천 검증. AI가 추천한 근로자를 데이터베이스에서 조회한 후보와 대조해 실제 후보인지, 대기 중인지, 같은 근로자가 중복으로 포함됐는지 확인했습니다. 직종별 인원과 예산도 검사했습니다. 예산만 초과한 조합은 초과 금액을 표시해 사무소가 임금을 조정한 뒤 승인할 수 있도록 했습니다.
  • 보고서 인용 검증. 보고서의 인용 출처를 Bedrock 검색 결과와 큐넷(Q-Net)의 자격 정보 조회 결과에 대조했습니다. 검색 결과에 없는 문서 ID가 들어오면 검증 오류가 발생하도록 구현하고 해당 사례를 테스트했습니다.

기술

Python, Strands Agents, Amazon Bedrock Knowledge Bases, Amazon S3 Vectors, DynamoDB, pytest

결과

팀은 건설사가 인력을 요청하면 인력사무소가 AI 추천안을 검토해 승인하고, 작업조 전원이 수락하면 배정이 확정되는 흐름을 구현했습니다. 근로자는 보고서에서 선택한 직종의 자격·역량 요건과 보완에 필요한 근거를 확인할 수 있습니다. 이 프로젝트로 클라우드 AI PBL 우수상을 받았습니다.
